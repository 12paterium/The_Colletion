# Meme 图片临时分拣流水线设计

## 目标

将放在仓库 `sorting/` 根目录中的图片进行一次性处理：WebP 转为 PNG、调用视觉模型生成中文名称并判断类别、随后把文件移动到 `sorting/梗图`、`sorting/表情`、`sorting/史` 或 `sorting/其他`。文件进入分类子目录后，本工具的工作即告结束；用户自行查看并搬运到最终图库。

## 范围

流水线只处理 `sorting/` 的直接子级文件，不递归扫描，因此已经进入四个分类子目录的图片不会再次处理。支持 `.png`、`.jpg`、`.jpeg`、`.webp` 和 `.gif`，扩展名匹配不区分大小写。视频、Python 脚本、压缩包以及其他非图片文件均忽略。

本次重构不实现历史记录、重复图片检测、最终图库搬运、嵌入检索、图形界面、人工确认队列或置信度评分。现有 `sort_history.json` 及相应忽略规则将删除。

## 架构

代码按职责拆分，但每张图片只发起一次视觉模型请求：

```text
scripts/main.py
    -> sorter.sort_directory()
        -> converter.convert_webp()
        -> marker.analyze_image()
        -> sorter.move_to_category()
        -> utils 中的共享文件工具
```

`main.py` 是入口空壳。`sorter.py` 是批处理模块，对外提供 `sort_directory(directory: Path = SORTING_DIR)`，生产入口使用默认的 `sorting/`，测试和一次性验证可以传入隔离目录。`marker.py` 隐藏视觉模型、提示词和提供商差异。`converter.py` 只负责格式转换。`utils.py` 保存多个模块确实共享的文件处理函数，不承载流程控制。

## 文件职责

### `scripts/main.py`

调用 `asyncio.run(sort_directory())`，将启动失败转换为简洁的终端错误和非零退出码，不包含图片处理实现。

### `scripts/marker.py`

保留 OpenAI 兼容提供商配置、请求限速和异步请求逻辑。核心接口接收图片路径，返回 `ImageDecision(mark: str, category: str)`，不重命名或移动文件。

模型必须通过一次请求返回：

```json
{
  "mark": "警察 你继续说",
  "category": "表情"
}
```

请求使用 JSON Object 输出模式。返回内容仍在本地通过 `json.loads` 校验：必须是对象，必须包含字符串类型的 `mark` 和 `category`，且分类只能是四个允许值之一。格式或字段不合法时，该图片失败并留在 `sorting/` 根目录，不进行第二次模型修复请求。

### `scripts/converter.py`

只转换 `sorting/` 根目录中的 WebP。静态 WebP 输出普通 PNG；动画 WebP 输出带 `.png` 扩展名的 APNG，并保留帧数、播放时长和循环设置。转换采用临时文件，确认输出能被 Pillow 重新打开后才替换为正式 PNG 并删除原 WebP。

若同名 PNG 已存在，转换结果使用 `_1`、`_2` 等后缀避免覆盖。转换失败时删除不完整的临时文件、保留原 WebP，并且不调用模型。转换成功但后续模型请求失败时，PNG 留在 `sorting/` 根目录，供下次运行继续处理。

### `scripts/sorter.py`

创建 `梗图`、`表情`、`史`、`其他` 四个输出目录，只枚举 `sorting/` 根目录的受支持图片。它负责并发调度以下步骤：

1. 需要时调用 converter 得到 PNG 路径。
2. 调用 marker 一次，取得名称和分类。
3. 清理名称并计算目标路径。
4. 将文件重命名并移动到对应子目录。
5. 输出逐图结果和最终成功/失败统计。

单张图片失败不会中止其他任务。移动目标重名时添加 `_1`、`_2` 等后缀，不覆盖已有图片。

### `scripts/utils.py`

提供受支持扩展名、图片 MIME 类型、图片转 data URL、Windows 文件名清理、唯一目标路径以及异步请求节流工具。所有函数只依据参数工作，不保存全局处理状态。

## 分类规则

模型按照以下顺序判断，以减少类别重叠：

1. 图片主要适合在聊天中直接表达反应、情绪或动作时，归为 `表情`。
2. 图片主要是聊天记录、帖子、推文、长文本或依赖故事上下文才能理解的离谱内容时，归为 `史`。
3. 图片用较短内容表达一个集中笑点、读完容易会心一笑时，归为 `梗图`。
4. 壁纸、插画、素材、普通照片、信息图或无法稳定归入前三类的内容，归为 `其他`。

名称延续当前中文互联网表情包风格。模型目标长度为 8 至 20 个字，允许空格，不允许路径或 Windows 文件名非法字符；本地清理后为空的名称视为失败。

## 数据流和失败行为

启动时先验证 `sorting/` 目录、API Key 和提供商配置。目录中的图片列表只获取一次；每个 WebP 转换后，当前任务改用产生的 PNG。模型调用和文件移动都按图片独立捕获异常。

只有模型结果通过本地校验后才执行分类移动。请求失败、JSON 无效、分类无效或文件操作失败的图片留在 `sorting/` 根目录。由于没有历史记录，下次运行会自然重试仍在根目录中的图片；已进入子目录的图片因不递归扫描而自然跳过。

## 配置

继续支持环境变量 `AI_PROVIDER`、`AI_MODEL`、`QWEN_API_KEY` 和 `SILICONFLOW_API_KEY`。默认提供商和模型沿用当前 `marker.py` 配置。并发数、请求间隔和超时保留为代码常量，不新增配置文件或复杂命令行参数。

## 测试

测试全部使用临时目录和伪造模型客户端，不访问真实 API，也不操作仓库中的 402 张待分拣图片。覆盖：

- 只扫描 `sorting/` 直接子级并忽略四个输出目录及非图片文件；
- 静态 WebP 转 PNG、动画 WebP 转 APNG、损坏 WebP 保留原件；
- 合法与非法模型 JSON、四个分类值和文件名清理；
- 四类目标移动、重名后缀和单图失败不影响其他图片；
- 完整流水线确保每张成功图片只调用模型一次。

## 50 张真实图片验收

自动化测试通过后，再使用真实模型进行一次性效果验收。验证从已经人工分类的图库中按固定随机种子分层抽取 50 张图片：`弔图` 13 张、`表情` 13 张、`史` 12 张、`杂篇` 12 张。期望分类映射为 `弔图 -> 梗图`、`表情 -> 表情`、`史 -> 史`、`杂篇 -> 其他`。

抽样只复制文件，不移动或重命名来源。副本放入固定隔离目录 `sorting/.validation/` 的直接子级，并调用 `sort_directory(validation_directory)`；默认生产入口不会扫描这个子目录，也不会触碰 `sorting/` 根目录中现有的待分拣图片。

验收收集并向用户报告以下结果：

- 每张图片的原文件名、新文件名、期望分类、实际分类和是否一致；
- 总体分类一致率以及四类各自的一致率；
- 所有成功文件是否位于 `.validation/梗图`、`.validation/表情`、`.validation/史` 或 `.validation/其他`；
- 是否出现越出验证目录的路径、覆盖已有文件或遗留根目录文件；
- 原始 50 张来源文件是否仍存在且内容哈希未变化；
- WebP 转换后的扩展名及静态或动画帧数是否正确。

分类一致率只作为效果对比数据，不设置自动通过阈值；名称质量由用户根据原文件名与新文件名对照判断。路径越界、覆盖来源文件或修改来源内容则属于验收失败。

结果全部收集后，无论验收成功或中途失败，都只删除解析后严格等于仓库 `sorting/.validation` 的验证目录。删除前拒绝符号链接或目录联接，不使用通配符，也不删除任何来源文件、`sorting/` 根目录待分拣图片或四个正式输出目录。
